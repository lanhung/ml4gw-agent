\title{An Agentic Orchestration Layer for Machine-Learning Gravitational-Wave Analysis: Typed Skill Contracts, Fail-Closed Execution and Calibrated Multi-Model Inference}

\author[0000-0000-0000-0000]{Fan Zhang}
\affiliation{TBD}

\begin{abstract}
Machine-learning pipelines now cover the full low-latency gravitational-wave workflow: detection (Aframe), parameter estimation (AMPLFI), unmodelled anomaly search (GWAK) and noise subtraction (DeepClean). Composing them for a given scientific request still requires expert judgement about data access, model applicability, significance calibration and compute. We present \agent, an orchestration layer in which a large language model or a deterministic planner turns a natural-language request into a directed acyclic graph of typed skills, each bound to a versioned contract (JSON-schema inputs and outputs, machine-checked preconditions, immutable model revisions) and executed by a fail-closed adapter that records every artifact by cryptographic hash. We evaluate the layer on three axes: planning quality on a benchmark of 317 prompts across three model backbones, including an adversarial suite that measures silent, plausible-but-wrong outcomes; scientific fidelity on the 90 events of GWTC-1, GWTC-2.1 and GWTC-3 processed end to end through Aframe, AMPLFI and GWAK on the LIGO Data Grid, compared with the catalog and with the published Aframe O3 search; and significance calibration from time-shifted backgrounds of 69 days for each of Aframe and GWAK together with injection campaigns. Aframe recovers 60 of the 76 analysed events at a one-per-day threshold with the published pattern of misses, AMPLFI covers the catalog chirp mass at the nominal 90\%, and without contracts a third of adversarial requests would have executed a plausible but wrong analysis. The code, contracts, calibration tables and run manifests are public.
\end{abstract}

\section{Introduction}
\label{sec:intro}

Machine learning now covers every stage of the low-latency
gravitational-wave workflow. Aframe detects binary black hole mergers
directly from strain with a median latency of about three seconds
\citep{aframe2025} and has run in the LIGO--Virgo--KAGRA (LVK) online
analysis since August 2025; AMPLFI produces posterior samples and sky maps
seconds later \citep{amplfi2025}; GWAK searches the same data for
unmodelled transients \citep{gwak2024}; DeepClean subtracts environmental
noise couplings using auxiliary witness channels \citep{deepclean2020}.
Offline, machine-learning searches of the third observing run (O3) have
reached the sensitivity of matched filtering for stellar-mass binaries and
have started to report their own candidates \citep{marx2025,koloniari2025,
silver2025}.

What has not been automated is the judgement that composes these tools for
a given scientific question: which data source can serve the request,
whether a model's training range and detector set apply, what threshold
turns a network output into a significance statement, whether an
expensive step is justified, and how every number in the answer can be
traced back to immutable inputs. This judgement is currently supplied by
experts writing scripts, and it is exactly the kind of task that large
language model (LLM) agents are being proposed for across the sciences.
Agents have planned and executed chemistry \citep{boiko2023,bran2024},
designed experimentally validated nanobodies \citep{swanson2025}, and in
astronomy interpreted multi-band galaxy photometry through an existing
modelling code \citep{sun2026} and driven cosmological parameter
inference \citep{laverick2024}.

The same studies expose the central risk. In an evaluation of an
astrophysical multi-agent system on eighteen tasks, the dominant failure
was not a crash but ``silent incorrect computation'': syntactically valid
code producing plausible but wrong results, without self-diagnosis
\citep{rawat2026}. A benchmark of twelve coding agents on
gravitational-wave problems found metric misuse, constraint violations and
fabricated results \citep{islam2026}. For a field whose results are
significance statements about rare events, an agent that occasionally
invents a number is worse than no agent.

This paper presents \agent, an orchestration layer built around that
constraint. Its design principle is that the agent may decide \emph{what}
to run but never \emph{whether a result is valid}: every capability is a
skill with a machine-checked contract, every adapter fails closed, every
model is pinned, every threshold comes from a recorded background study,
and every artifact is hashed into a manifest. We evaluate the layer on
three axes. Planning: a benchmark of 317 natural-language requests across
three LLM backbones, including an adversarial suite that measures how
often a plausible-but-wrong analysis would have executed with and without
contracts (Section~\ref{sec:planning}). Scientific fidelity: the 90 events
of GWTC-1, GWTC-2.1 and GWTC-3 processed end to end through Aframe, AMPLFI
and GWAK on the LIGO Data Grid, compared with the catalog and with the
published Aframe O3 search (Section~\ref{sec:population}). Calibration:
time-shifted backgrounds and injection campaigns for the shipped model
revisions, and a witness-channel noise-subtraction route with a
signal-preservation check (Section~\ref{sec:calibration}). Section~\ref{sec:cost}
reports the measured cost, and Section~\ref{sec:discussion} discusses what
this design does and does not solve.

\section{Design}
\label{sec:design}

\agent\ separates three concerns that are usually entangled in an analysis
script: \emph{what} a request means (planning), \emph{whether} a step may
run (contracts and preconditions), and \emph{how} it runs (adapters and
executors). Figure~\ref{fig:arch} summarises the data flow.

\subsection{Skill contracts}
\label{sec:contracts}
Every capability the agent can schedule is a \emph{skill} described by a
versioned YAML manifest: a name (\texttt{aframe.detect},
\texttt{amplfi.pe}, \texttt{gwak.scan}, \texttt{deepclean.clean}, \ldots), a
JSON-schema for inputs and for outputs with \texttt{additionalProperties:
false}, a list of machine-checkable preconditions, output validations
(fields that must exist, artifacts that must be on disk), resource
estimates, a risk level with an approval flag, and the adapter that
implements it. Model-bearing skills take an immutable \texttt{model\_revision}
(a git commit or a SHA-256 of the weights) and refuse \texttt{UNPINNED}.
Contracts are the only interface the planner sees; the planner cannot
invent parameters or skip a precondition, because plan validation rejects
any task whose parameters fail the input schema or whose references point to
outputs that no upstream task declares.

\subsection{Planning}
\label{sec:planner}
A \emph{plan} is a directed acyclic graph of tasks with typed references
(\texttt{\$\{fetch\_data.outputs.strain\_artifact\}}) and optional conditions
evaluated at run time (\texttt{when: \$\{inspect\_data.outputs.quality\_passed\}
truthy}). Two planners produce plans. The deterministic baseline planner
maps a request to routes by lexical intent (detection, parameter
estimation, anomaly scan, cleaning) and encodes the domain rules: AMPLFI is
conditioned on an Aframe candidate; GWAK needs its own 4096\,Hz fetch;
DeepClean cleaning runs only after its applicability check reports
\texttt{applicable}; an unbounded request (``scan all of O3'') is refused at
planning time. The LLM planner asks a language model for a plan under a
structured-output schema derived from the contracts, validates it, and
falls back to the baseline with a recorded reason when validation or the
API fails. Both produce the same plan object, so every downstream guarantee
is independent of the planner.

\subsection{Fail-closed adapters and provenance}
\label{sec:adapters}
An adapter is the code that runs a skill. Adapters never fabricate: when a
model, a credential, a witness channel or a calibration is missing, the
task fails with a reason and dependent tasks are skipped, not executed with
defaults. Each run produces a manifest that records the plan, every task's
resolved parameters, outputs, validations, warnings, timings, the packages
and model revisions used, and the SHA-256 of every artifact. Mock adapters
exist for software testing and are labelled \texttt{simulated: true} in every
output; no mock result can enter a scientific record.

\subsection{Calibration as a first-class object}
\label{sec:calib}
Detection statistics are only meaningful against a background. The layer
ships calibration tables keyed by model revision: thresholds at named false
alarm rates from time-shifted background studies, with the livetime that
supports them, and a FAR curve so that any score can be reported as a
measured background rate. The planner resolves a requested FAR to a
threshold for the pinned revision; if none is measurable at that rate for
that revision, the plan carries a warning and the adapter marks the flag as
uncalibrated. Section~\ref{sec:calibration} describes the studies.

\subsection{Executors and cost policy}
\label{sec:executors}
A plan runs locally, on an HTCondor pool (the LIGO Data Grid), or on a
remote GPU host over SSH; a Kubernetes executor is registered as deferred.
Before submission the runtime estimates CPU- and GPU-hours, memory and
transfer volume from the contracts and the timings measured in earlier
runs, checks them against a budget policy, and requires explicit
authorisation above a configurable GPU-hour limit. Long GPS-time requests
are split into overlapping segments, submitted as sub-plans and merged
without duplicate candidates.

\section{Evaluation of planning}
\label{sec:planning}

\subsection{Benchmark}
The benchmark (\texttt{benchmarks/v2\_prompts.yaml}) holds 317 requests
generated from templates crossed with the 90 GWTC events: 232 nominal
routes (single skills, composed routes, GPS-time and named events), 15
ambiguous requests, 19 edge cases (superevent identifiers, mixed-language
phrasing, two events in one request, non-public identifiers) and 51
adversarial requests in six guardrail families (refuse unbounded requests,
registered skills only, DeepClean only after its applicability check,
AMPLFI only on a candidate, policy limits on windows and sample counts,
pinned model revisions). 173 prompts are English, 113 Chinese and 31
mixed. The expected skill sequence of each case is the deterministic
planner's answer, so the benchmark is satisfiable by construction.

\subsection{Backbones}
Table~\ref{tab:planner} summarises three Claude backbones. Opus was run on
every case with three repeats; the two smaller models on a stratified
62-case sample with one repeat, after the first full pass exhausted the
project's API budget. All backbones produce only valid, executable plans
through the contract path. Exact agreement with the deterministic route is
0.68--0.77 and superset compatibility 0.74--0.77; the disagreement is
concentrated in ambiguous prompts, where the LLM planners add analyses the
baseline leaves out. Opus reproduces the same plan across three repeats in
only 37\% of cases, which is why the deterministic planner remains the
default for scientific runs and the LLM planner is an interface.

\subsection{Silent-failure suite}
For every adversarial case we score two paths (Table~\ref{tab:guardrails}):
the contract path used in production (schema validation, registered
skills, declared references, execution policy, one repair round, then
deterministic fallback with a recorded reason) and a contract-free
counterfactual in which the same model's first proposal is taken at face
value. Without contracts, 30--35\% of adversarial requests would have
executed a plausible but wrong analysis: unbounded windows, unpinned
models, AMPLFI without a candidate, no refusal of unbounded requests. With
contracts the silently-wrong rate is zero for Sonnet and Haiku. The suite
also found two gaps in the validator itself: a made-up revision string
(\texttt{v99}) passed a policy that rejected only the literal
\texttt{UNPINNED} (one Opus case, 0.020), and plans scheduling AMPLFI
without a candidate condition passed the contracts, which cannot express
cross-task rules (two Haiku cases). Both rules were added to the planner
validator and the Haiku rerun is at 1.000; we report the pre-fix Opus row
unchanged.

\section{Scientific validation on GWTC events}
\label{sec:population}

\subsection{Setup on the LIGO Data Grid}
We submitted one request per event for the 90 events of GWTC-1, GWTC-2.1
and GWTC-3 \citep{gwtc21,gwtc3}: fetch 128 s of public GWOSC strain around
the catalog time \citep{gwosc}, check data quality, run Aframe and AMPLFI,
scan the window with GWAK at 4096 Hz and reconcile. Each request became one
whole-plan HTCondor job on the Caltech LIGO Data Grid pool through the
agent's HTCondor executor, with the deterministic planner, the pinned model
revisions and the calibrated one-per-day thresholds. Every outcome below is
read from the run manifests; no event was retried or edited by hand.

Table~\ref{tab:stages} shows where events left the pipeline. Seven events
have no public H1 or L1 data in the window (single-LIGO events); the data
adapter failed closed with that reason. Seven more failed the data-quality
gate (non-finite H1 samples or an uncovered \texttt{H1\_DATA} flag), so
their Aframe, AMPLFI and GWAK tasks were skipped by the plan's condition
rather than run on bad data. The remaining 76 events were analysed end to
end.

\subsection{Detection}
Aframe reports a candidate within 2 s of the catalog time above the
calibrated one-per-day threshold for 60 of the 76 analysed events, and for
60 of the 71 whose secondary mass lies inside the model's training range
($m_2 \geq 5\,M_\odot$). The five misses outside the training range are the
neutron-star events GW170817, GW200115, GW191219, GW200210 and GW190917
(GW190425 and GW190814 were quality-gated); the eleven binary black hole misses have
catalog network SNR 4.7--12.0 (median 7.9). Recovery by SNR is 2/8 below
8, 18/23 at 8--10, 12/15 at 10--12 and 28/30 above 12. For the candidates
the coalescence time agrees with the catalog to 0.037 s (median absolute
offset; 90\% within 0.083 s). The published Aframe O3 search recovered 38
of 70 H1L1 GWTC-3 events against a 100-year background \citep{marx2025};
our targeted analysis at a much looser threshold is not a competing
sensitivity, but it reproduces the same pattern of misses: sources below
the training range and SNR below about 12.

\subsection{Parameter estimation}
For the 60 candidates AMPLFI's 90\% interval on the source-frame chirp mass
contains the catalog value in 54 cases (the nominal 90\%), with a median
ratio of AMPLFI median to catalog of 1.07. Luminosity distances are biased
low by about 30\% (median ratio 0.71; 37 of 60 intervals cover the catalog),
a known property of the two-detector model relative to three-detector
catalog posteriors \citep{amplfi2025}. Figure~\ref{fig:population} shows
the comparison.

\subsection{Anomaly scores}
GWAK scores all 76 windows. The target kernel is the loudest of its window
for 31 events and within the top ten for a further 16 (median $z$-score
8.8), but no event exceeds the one-per-day cut, which sits at the level of
single-detector glitches (Section~\ref{sec:calibration}). Each manifest
records the measured background rate at the target score instead.

\section{Significance calibration}
\label{sec:calibration}

\subsection{Time-shifted backgrounds}
For each shipped model revision the agent carries a background study made
with the same adapters that run the science: public GWOSC stretches with
catalog events excised, the L1 stream shifted against H1 by multiples of
8 s, every lag scored, peaks clustered within 8 s, and the false-alarm
rate at a statistic $x$ taken as the number of peaks at or above $x$ per
unit livetime. The tables in the repository (\texttt{calibration/}) record
the livetime, the loudest peaks, thresholds at named rates and a full FAR
curve, keyed by revision; the planner resolves a requested rate to a
threshold and refuses to report a rate the livetime cannot support (a
rate below one event per livetime is a bound, not a measurement).

The first study (three stretches, 123 lags, 5.5 d) fixed the one-per-day
thresholds used throughout this paper: 2.70 on Aframe's integrated
statistic and 25.55 on the GWAK score. The extended study (36 event-free
H1L1 stretches in O2 and O3, 40 lags each, run as 72 HTCondor shards on the
Data Grid) reaches 68.6 d (Aframe, 546\,923 peaks) and 68.9 d (GWAK, 554\,049 peaks)
of livetime and makes the one-per-month rate measurable: Aframe 2.99 per
day and 4.40 per month, GWAK 27.85 per day and 28.23 per month. The
population run and the injections below used the first study's cuts,
recorded in every manifest; against the extended study 59 of the 60
population candidates remain above the one-per-day cut and 54 above the
one-per-month cut. The GWAK background is bimodal: a Gaussian
bulk ending near 14 and, in every lag of every stretch, one peak at
20--26. A time shift moves only one detector, so a loud single-detector
transient recurs in every lag; these are glitches, and the anomaly
detector scores them above the two loudest catalog mergers (15.4 and
14.3). The one-per-day cut therefore sits at the glitch level, and the
agent reports the measured rate at an event's score
(\texttt{target\_far\_per\_year}, about $10^4$ per year for GW150914 and
GW190521 against $3\times10^6$ per year for the noise window) rather than
a flag.

\subsection{Injections}
To measure what the thresholds mean for signals we injected IMRPhenomD
binary black hole waveforms (component masses uniform in
10--80 $M_\odot$, aligned spins uniform in $\pm0.5$, isotropic sky) into
cached public O1--O3 noise around three catalog events, scaled to network
optimal SNR 6--30 with 25 injections per SNR, plus 25 control windows, and
ran the real Aframe and GWAK adapters on each artifact
(Table~\ref{tab:injections}). Aframe reaches 50\% efficiency at network
SNR 8.2 and 90\% at 11.8 at the one-per-day cut with no false candidate in
the controls, and recovers the coalescence time to 12 ms (median) with
90\% within 51 ms. GWAK never crosses its one-per-day cut, as the
glitch-dominated background predicts; the injection is the loudest kernel
of its window in 88\% of cases above SNR 15, and the misses at high SNR
are all long, low-mass inspirals ($m_1 \leq 24\,M_\odot$) that do not fit a
0.5 s kernel.

\subsection{DeepClean applicability and signal preservation}
Noise subtraction is the step where an agent can most easily destroy
science, so it is guarded twice. \texttt{deepclean.check\_applicability}
passes only when the strain source can serve witness channels (public
GWOSC strain cannot), a reviewed coupling configuration covers the
detector and interval, and the witness channels are actually fetched;
\texttt{deepclean.clean} runs only under that verdict, verifies the
weights against the pinned hash, subtracts a band-limited estimate that
depends on the witnesses alone, and reports \texttt{applicable: false} if
the in-band ASD does not improve or the out-of-band ASD moves by more than
5\%. On public data the check fails closed with the reason and the plan
skips cleaning; on collaboration data (not part of this paper's evidence)
a self-trained 60 Hz mains-coupling model reduces the line by a factor of
seven on held-out data and leaves the out-of-band spectrum unchanged to
$10^{-7}$. Because the estimate is a function of the witnesses only,
injected signals pass through unchanged (match 1.000 to double precision
over 32 injections); this is a structural regression check on the
implementation, not an independent physics result, and a reviewed
injection tolerance remains open.

\section{Cost and scalability}
\label{sec:cost}

Every manifest records per-task wall-clock time, so cost is measured, not
estimated (Table~\ref{tab:cost}). For a 128 s two-detector window on one
GPU the science tasks are cheap: Aframe 11 s (median over 93 runs), AMPLFI
3 s, GWAK 1 s at 1/16 s stride; the data fetch dominates when the GWOSC
file is not cached (up to 140 s) and is negligible when it is. The whole
population run consumed 0.35 GPU-hours of compute for 83 completed events
(median 23 s wall-clock per event on the worker, maximum 57 s); the
elapsed hours were queue time on a shared pool, not computation. The
contract estimates that the budget policy uses before submission are
conservative for the GPU steps (AMPLFI estimated at 15 s, GWAK at 30 s) and
optimistic for Aframe (5 s), and are updated from these measurements.

Two operational lessons from the population run are recorded in the
manifests rather than hidden. First, 517 of the pool's GPU slots run on
x86-64-v1 CPUs without AVX, on which PyTorch dies with an illegal
instruction; the first pass lost 36 workers this way and the executor now
requires \texttt{Microarch $\geq$ x86-64-v2}. Second, the time-shift
background shards for Aframe need 32 GB of memory, twice the contract
default, which the cgroup limit exposed on the first shard. Both are the
kind of fact a human operator learns once and forgets; here they are
configuration checked into the repository.

Long requests are split automatically: a GPS-time window above the policy
limit becomes overlapping segment sub-plans (8 s overlap) submitted as
separate jobs and merged without duplicate candidates; the budget is
checked once for the whole scan.

\section{Discussion}
\label{sec:discussion}

\paragraph{What the contracts buy.} The adversarial suite gives a
quantitative answer to the concern raised by \citet{rawat2026} and
\citet{islam2026}: with the same language models, taking the first
proposal at face value would have executed a plausible but wrong analysis
for a third of adversarial requests, whereas the contract path executed
none for two of the three backbones and one in fifty for the third, and
the suite itself found the two validator gaps that produced that one. The
price is agreement with an expert route of about 70--77\% on ordinary
requests, concentrated in ambiguous phrasing, and a 24\% fallback rate for
the smallest backbone. Because the fallback is the deterministic planner,
a weaker or cheaper model degrades the agent's helpfulness, not its
correctness; this is the property that lets the layer expose free and
open-weight models through the same interface.

\paragraph{What the population run does and does not show.} The
end-to-end run reproduces the published behaviour of the underlying
models on public data with full provenance: the Aframe recovery pattern
(training range and SNR), AMPLFI's nominal chirp-mass coverage and known
distance bias, and GWAK's separation of signals from Gaussian background
but not from glitches. It is not a search and makes no new astrophysical
claim; its value is that every number is traceable to a manifest, a pinned
revision and a calibration record, and that the 14 events the pipeline
declined to analyse carry the reason.

\paragraph{Limits.} Significance is only as good as the background
livetime: one-per-day thresholds from days of time slides, one-per-month
from the extended study, nothing tighter. GWAK's threshold is set by
glitches, so an anomaly flag at astrophysically interesting rates needs a
glitch veto or a glitch-aware metric that upstream has not yet released.
DeepClean is a single, self-trained 60 Hz coupling and its preservation
check is structural (witness-only prediction), not an injection study at
reviewed tolerance. The LLM planner is non-deterministic across repeats
(37\% identical plans for the strongest model), which is why the
deterministic planner is the default for scientific runs.

\section{Conclusions}
\label{sec:conclusions}

We have built and evaluated an orchestration layer that lets a language
model, or a deterministic router, compose production machine-learning
pipelines for gravitational-wave analysis without being trusted with the
validity of any result. Typed skill contracts, fail-closed adapters,
pinned model revisions, calibration tables keyed by revision and hashed
manifests make the agent's science auditable; a benchmark of 317 requests
and an adversarial suite measure the cost and the benefit; and a
population run over 90 catalog events on the LIGO Data Grid shows the
layer reproducing published model behaviour end to end at 0.35
GPU-hours. The code, contracts, benchmarks, calibration tables and every
run manifest are public.
