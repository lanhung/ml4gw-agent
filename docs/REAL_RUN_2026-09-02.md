# Real Buoy acceptance attempt — 2026-09-02

## Outcome

The real adapter and model environment reached public-data acquisition, but the
scientific run could not complete because this execution environment cannot
reach the GWOSC API. Repeated requests to
`https://gwosc.org/api/v2/event-versions/GW150914` returned HTTP 502. The run
was stopped rather than allowing unbounded retries.

This is recorded as an external infrastructure blocker. No real detection
statistic or posterior is claimed.

## What passed before the blocker

- `ml4gw-buoy==0.6.1` installed and imported on Python 3.12.
- Aframe model revision
  `3c947f6ded4a8b4b5a5dd7620d3e2e710e1716f4` downloaded and loaded.
- AMPLFI model revision
  `8b97d2f8459d04924cb010dfee0262260bf3da80` downloaded and loaded for both HL
  and HLV configurations.
- Buoy entered `Fetching or loading data` for GW150914.
- The agent preserved logs and produced a failure/partial report.

## Dependency drift found and fixed

PyPI metadata admitted newer dependencies than the reviewed Buoy lockfile:

1. `jsonargparse==4.52.0` rejected the serialized `GroupNorm1DGetter` callable
   configuration. The reviewed upstream lock uses `4.50.0`.
2. `zuko==1.6.0` renamed normalizing-flow base buffers (`_0`/`_1` versus
   `loc`/`scale`), so the published AMPLFI state dict did not load. The reviewed
   upstream lock uses `1.4.1`.

The optional `buoy` environment now pins both reviewed versions. This is an
example of why a scientific agent must record the complete environment rather
than only a top-level package version.

## Runtime issues found and fixed

- The Python API runner now converts jsonargparse `SystemExit` into an audited
  adapter failure rather than leaving the manifest incomplete.
- Operator interruption now checkpoints task/run status as `cancelled`.
- Intended adapter invocation metadata is written before execution, so failed
  calls remain explainable.
- Buoy logs stream to files during execution.
- `doctor` performs a real CLI import smoke test instead of only checking that a
  file named `buoy` exists.

## Container-only workaround

This validation container exposes inconsistent PID namespaces to child Python
processes, causing Dask's optional psutil CPU-affinity probe to fail. A temporary
process-local affinity shim was used solely to reach the scientific workload.
It is not part of the project or the production adapter.
